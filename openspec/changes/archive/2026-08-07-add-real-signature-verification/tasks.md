## 1. Pin the signed encoding first

The encoding is the interoperability contract. It must be fixed by vectors before either language
signs anything, or the two will disagree in a way that only surfaces when a phone and a desktop are
paired.

- [x] 1.1 Create `shared/testvectors/signing_payload.json`. Each case carries the four signed fields (`sender`, `command`, `createdAtMillis`, `nonce`) and `expectedBytesHex` — the canonical encoding as lowercase hex. Cases must include: a minimal case; a case with multi-byte UTF-8 in `sender`; a case whose `nonce` contains `|` and `:` (the delimiters a naive encoder would have picked, per design D3); two cases differing only in where a field boundary falls (e.g. sender `ab` + nonce `c` versus sender `a` + nonce `bc`) whose encodings must differ; and a case with `createdAtMillis` at zero.
- [x] 1.2 Add a `signing_payload.json` section to `shared/testvectors/README.md`: the field order, the length-prefix format and its width, the millis encoding for the instant, and the D3 reason length-prefixing was chosen over a delimiter — including the forgery example, so a later contributor cannot "simplify" it back.
- [x] 1.3 Add a signing-payload runner to `desktop/src-tauri/tests/shared_vectors.rs` asserting the produced bytes equal `expectedBytesHex` exactly, plus a required-id guard listing the boundary-ambiguity pair and the delimiter case.
- [x] 1.4 Mirror the runner in `mobile/test/shared/shared_vectors_test.dart` with the same required-id guard ← (verify: both suites fail for missing implementation, not for parse errors; the two boundary-ambiguity cases have genuinely different `expectedBytesHex` — if they match, the encoding is forgeable and the vectors are wrong)

- [x] 2.2 Create `desktop/src-tauri/src/domain/signing_payload.rs`: a pure `encode(sender, command, created_at, nonce) -> Vec<u8>` implementing the D3 length-prefixed concatenation. Document the forgery argument in the module doc comment.

## 3. Rust — remove the boolean, verify inside the rule

This is the change that pays the blocker. `signature_verified` must cease to exist.

- [x] 3.1 In `desktop/src-tauri/src/domain/command_envelope.rs`, **remove** the `signature_verified: bool` field and add `signature: Vec<u8>`. Per design D1 this is a removal, not an addition — both fields must not coexist, or a call site will assert rather than verify. Update the doc comment to say why.
- [x] 3.2 Add `verifying_keys: HashMap<DeviceId, VerifyingKey>` to `CommandTargetState` in `domain/command_acceptance.rs`.
- [x] 3.3 Make `evaluate_command` perform verification as its first check: encode the payload from the envelope, look up the key for the claimed sender, verify. A sender with no key is `AuthenticityUnverified` — **not** a new reason, per design D2, because distinguishing "unknown device" from "bad signature" leaks which device ids exist.
- [x] 3.4 Follow the compiler through every construction site of `CommandEnvelope` in tests and fixtures, replacing the boolean with a real signature. Tests that previously passed `signature_verified: true` must now sign with a test key — do not introduce a helper that fakes verification.
- [x] 3.5 Rewrite the `signature_verified` field in `shared/testvectors/command_acceptance.json` into real signature bytes, generated by the implementation. Cases that were `signature_verified: false` become cases bearing a signature that does not verify. Every other field of every case must be unchanged — diff to confirm only the one field's replacement.
- [x] 3.6 Update both harness runners for the new case shape ← (verify: `grep -r signature_verified` across `desktop/` and `mobile/` returns nothing outside archived openspec artifacts; all pre-existing acceptance cases still assert the same expected decision they did before, with only the input field changed)

## 4. Rust — transport seam

It must expose **no** member by which an implementation could assert authenticity — no `verified`, `trusted`, `attested`, or `authentic` in any name, per design D8.
